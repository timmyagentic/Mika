# 本地详细 Trace

在调试版或性能测试版的「设置 → 开发者选项 → 运行记录」打开「记录详细 Trace」，从下一次任务开始采集。开关默认关闭，关闭即停止当前采集。正式版不启动详细采集。已保留的详细归档可以从对应运行的「查看过程」打开。

每次运行有一个根 span。主循环中实际发送的模型请求、顶层工具调用各有自己的子 span。同一步里重发的请求分别计数。记录包括步号、尝试次数、耗时、结束状态和服务商上报的用量。缓存未上报时显示「未上报」，显式零单独保留。

四种模型接口在各自最终的序列化请求上比较相邻调用的第一个变化块。采集按协议保留指令、工具定义和消息的原始块位置，图像记录尺寸与指纹。查看历史时可在某次尝试中分页对照脱敏请求和可见回复。

「保存本次 Trace」默认导出标准 OTLP Protobuf 文件，仅包含诊断元数据。显式勾选「附带脱敏正文」后，导出 ZIP，内含同一份 `trace.pb` 和按 span ID 命名的正文。根 span 的 `mika.trace.partial_reasons` 汇总部分记录的原因，模型 span 上的 `mika.trace.truncated` 事件包含块位置与原因。旧归档重新导出时沿用已有清单可证明的位置。

私有归档总容量默认 100 MiB，可在开发者选项中设置。需要空间时先清理最旧的已结束运行，保护正在录制或导出的归档。单次正文预算 8 MiB，最多 1,024 个子 span。手动保存的文件由用户管理。
